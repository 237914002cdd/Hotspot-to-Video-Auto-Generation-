# Pipeline Studio 使用指南

当前版本服务个人创作者与小团队的本地工作区。视频是可播放、可下载的无声文字动效 MP4；AI、配音、素材剪辑和社交账号自动发布留待后续接入。

## 启动与检查

安装 Node.js 22+、FFmpeg（含 ffprobe），然后在仓库的 `看板` 目录运行：

```powershell
npm ci
npm run setup:browser
npm run build
npm start
```

打开 http://127.0.0.1:3456 。服务默认仅在本机可用。进入「平台设置」查看渲染环境状态；Chromium、FFmpeg、ffprobe 都就绪后才能渲染。关闭运行服务的终端会停止后台；同一个工作区只启动一个服务。

## 从选题到成片

1. 在「热点」获取带来源的资讯，或点击「新建选题」手动录入。热点不是已核实事实，发布前应核对原始来源。四维评分帮助排序，不预测流量。
2. 从选题创建项目，进入工作室。相同中文标题也可以拥有独立项目。
3. 修改并保存「内容方案」与「发布文案」。点击生成模板草稿，将方案分为可编辑场景。内容超出容量时会明确报错，请主动精简，不会静默截断。
4. 选择主题和画幅，调整每个场景的标题、正文与时长。最多 12 个场景，总时长最多 120 秒；每场景 2–15 秒，标题 80 字、正文 260 字且最多 6 行。
5. 保存分镜并开始渲染。页面显示真实进度，可以离开工作室再返回；刷新后也能看到任务。服务中断后任务明确标记失败，可重新渲染。
6. 完成后播放 MP4，并下载视频、SRT 字幕、SVG 封面、方案或文案。当前画幅为竖屏 720×1280、横屏 1280×720、方形 900×900，24fps。
7. 在「封面」调整文字并保存。文字会按字段区域换行与缩放。确认成片和封面后归档；分镜改动后，旧视频会标记需要重渲染，不能把过期视频误归档。

每次成功渲染使用独立版本目录；失败或取消不会覆盖上一条成功成片。动态预览对应已保存的分镜，编辑后先保存再预览。

## 发布与复盘

在内容日历安排发布日期和目标平台；实际发布由你在对应平台完成，再更新本地发布记录。此操作不会自动向抖音或小红书发送内容。

从已发布记录录入平台真实指标。没有取得的指标留空；同一发布记录、平台与采集日期会更新原记录，避免重复累计。总览按最新快照统计播放数据，净增关注允许负数。复盘笔记记录有效的标题、开场和改进方向，不会生成虚构收入或涨粉数据。

## 保存冲突与备份

若另一个标签页修改了同一份数据，旧表单保存会显示冲突。先复制未保存文字，再重新打开项目取得最新版本并合并。不要反复点击保存来覆盖其他修改。

设置页可导出工作区 JSON，包含结构化业务记录，**不包含视频等文件**。完整备份需要复制 `看板/data/` 和 `项目/` 两个目录。恢复前停止服务，先保留当前目录副本，再放入备份。文件损坏时系统会报错；不会自动清空数据作为“修复”。

## 历史项目与常见问题

- 历史项目内容仍可读取。旧版依赖外部脚本的 HTML 在受限预览中可能无法播放，需转换为当前分镜后重新渲染。
- 获取热点失败时查看各来源状态；旧数据会保留，可以继续手工录入选题。
- 渲染环境未就绪：运行 `npm run setup:browser`，确认终端能执行 `ffmpeg -version` 和 `ffprobe -version`。也可以使用 README 中的绝对路径环境变量。
- 视频无法在某个嵌入式浏览器播放：先下载 MP4 在系统播放器或常规浏览器核对。渲染失败信息与浏览器播放错误应分别处理，不能仅凭进度 100% 判断观看体验。
- 这套本地服务没有多人鉴权、云端备份或计费系统，不应直接暴露到公网。
