# Pipeline Studio：个人创作者平台与商业化方案

研究与判断日期：2026-09-23。定位已由项目所有者确认：个人创作者及小团队；保留当前视觉语言。

## 产品承诺

帮助中文知识类、工具教程类创作者，把值得做的选题推进为可审核、可下载、可追踪表现的视频。第一目标是减少创作断点和重复操作。一个项目包含选题依据、内容方案、分镜、封面、成片、发布记录和复盘；每项结果都有对应文件或记录。

平台的核心衡量指标是每周实际发布且完成复盘的作品数。辅助指标是首次成功导出耗时、渲染成功率、选题到发布转化率、每条内容的实际制作成本。播放、收入不由热度分推算。

## 商业案例与取舍

| 参考 | 可核实的商业机制/案例 | 本项目采用的原则 |
|---|---|---|
| OpusClip / Audacy | 官方客户案例称，将直播内容转成短片并分发，在参与电台累计获得十亿级播放；案例强调没有随产量同步增加人员。属于供应商客户案例，不能推导成本、利润或保证复现。 | 从可交付的内容倒推工作流；任务完成必须有可播放成片，不能只有“已生成”提示。 |
| OpusClip / Chili Piper | 2024-08-15 的客户案例指出，挑选片段及多人反复讨论是制作瓶颈，价值在于缩短选片和制作过程。 | 保存、查看、修改应是不同操作；查看不能重新生成并覆盖，草稿应保留人的审核权。 |
| Descript | 官方收费页按个人/创作者/团队分层，并区分媒体时长与 AI credits；团队方案包含品牌协作能力。 | 本地基础工作流保持低成本；未来云渲染和模型调用按资源计量，品牌模板和协作作为团队价值。 |
| Buffer | 官方收费页将想法、草稿、排期、分析、访问权限与审批工作流组合销售；按渠道计费。 | 发布计划和表现记录必须关联作品、平台、日期；只有实际获得渠道授权才提供自动发布。 |

## 首个可用版本的边界

1. 热点来自明确来源，记录抓取状态；失败保留已有数据，人工选题始终可用。规则评分说明维度，不包装成模型分析或爆款概率。
2. 内容工作室编辑方案、文案、分镜、时长、主题和画幅。模板只整理用户输入，不捏造研究结论。每次预览反映已保存内容。
3. 本地 Chromium + FFmpeg 输出真实文字动效 MP4 与 SRT，三种画幅；当前无音轨。队列、进度、取消、重复任务保护、重启中断说明都有持久记录。
4. 封面从字段重新生成，成片和发布文案可下载，归档有实际资产门槛。
5. 日历是人工发布计划/记录；复盘是人工录入的平台表现，不假设已经调用抖音/小红书接口。
6. 默认只监听本机。这个版本是本地工作区，不是已上线的多租户 SaaS；不收取订阅费用、不伪造用户系统。

## 商业验证顺序

先邀请 5–10 位同类创作者进行四周试用，逐条记录任务耗时、导出成功、修改原因、发布与复盘。建议达标门槛：大多数试用者每周完成至少两条真实作品；能说明相对原流程节省了哪一步；愿意再次使用，而不只是评价界面好看。这些是验证目标，不是已实现结果。

验证后再确定付费方案，而不是先堆套餐页面。可测试三类产品：

- 本地创作者版：选题、内容管理、模板、手工日历和数据导出。建立用户信任和迁移成本。
- 创作者订阅：云备份、品牌模板、云渲染分钟数及明确的模型额度；超额调用事先显示成本并让用户确认。
- 小团队版：共享项目、角色权限、审核、版本记录与客户交付。按活跃制作成员收费，避免只读审阅者挤占制作席位。

价格需由真实试用反馈和成本计算决定。单位毛利模型应纳入模型费用、渲染分钟、存储与下载流量、失败重试和支持成本；失败任务不能无限消耗额度。现阶段不预设营收、用户数量或“爆款率”。

## 后续必须另外验收的能力

| 能力 | 依赖与验收 |
|---|---|
| AI 研究/脚本与配音 | 配置选定服务的凭据、模型和费用边界；真实调用、失败处理和内容审核；禁止将当前模板当作已接入 AI。 |
| 素材视频编辑 | 媒体导入、可用授权、音画同步、字幕校验、时轴和导出；当前文字动效不能替代通用剪辑器。 |
| 抖音/小红书自动发布及数据同步 | 渠道开放能力、应用审核、账号 OAuth、令牌续期、失败回执；未授权时保持人工记录模式。 |
| 对外 SaaS | 登录、多租户隔离、数据库事务、对象存储、任务队列、访问控制、备份恢复、监控和负载验证。单机 JSON 不能冒充多人公网生产基础设施。 |
| 支付订阅 | 收款主体、支付服务、回调签名、订阅状态、退款和对账；没有这些条件不放可点击的假支付入口。 |

未来优先级应来自实际用户卡住的位置：先完成作品，再评估云服务和多人协作。每个阶段用真实产物和行为验收，不以页面数量代表完成度。
